# 地块与项目的独立链接

## 维护规则

- 项目主表沿用“去化表项目名、克而瑞项目名、住建委备案名”的名称对照。
- 新增“关联地块”双向关联到同一个 Base 内的“地块目录”，地块目录反向显示“关联项目”。双方都支持多条记录。
- `projectCode` 填外部数据模块认可的真实项目编码，不使用飞书记录 ID、序号或住建委的 projectID 代替。
- “地块关联状态”独立于原来的“是否确认匹配”。确认本行所有关联地块后选择“已确认”；存在分期、组团争议时保留“需人工确认”。
- “地块关联依据”记录核对依据。项目名称相似只可用于找候选，不能自动确认。
- 一个地块对应多个项目时，网页项目列分行列出每个项目。每个有编码的项目是独立超链接；缺少编码时显示名称，不猜测链接。
- 网页展示名称依次取去化表项目名、克而瑞项目名、住建委备案名。不拆分名称中的斜杠来猜测项目数量，也不合并不同分期。

## 本地导入

`scripts/import_land_tracker_project_links.py` 通过已授权的 `lark-cli --as user` 读取项目表和其“关联地块”指向的目录，不修改飞书。需要当前 CLI 的 Base JSON 记录接口。

```sh
python scripts/import_land_tracker_project_links.py --base-url '<项目主表完整URL>'
```

默认只生成 `reports/land-project-links/proposed.html` 和校验摘要。确认后增加 `--apply` 更新本地正式 HTML；网页仍是可直接打开的静态文件。

只按完整地块编号连接，不按名称或列表序号连接。导入使用“已确认”的完整关系快照：被撤销的关联会移除；旧项目名称、金额、证照和来源不被覆盖。编码冲突、关联目标缺失、分页重复或读取期间版本变化会终止导入。

数据内嵌格式：

```json
{
  "landCode": "实际官方地块编号",
  "linkedProjects": [
    {"projectName": "项目名称", "projectCode": "真实编码"},
    {"projectName": "另一个项目", "projectCode": ""}
  ]
}
```

官方日更采集及证照补全会保留 `linkedProjects`。手工导入命令仍可使用；每日匹配与导入由下面的新命令完成。个人飞书凭据不放入网页或 GitHub，原有飞书地块采集工作流不改动。

## 自动匹配与同步

`scripts/sync_land_tracker_project_links.py` 复用现有采集结果及项目关联导入器，不再次重复抓取全部官方证照。

```sh
python scripts/sync_land_tracker_project_links.py --refresh-source --apply --lark-cli '<已授权CLI路径>'
```

不带 `--apply` 时仅试算并生成报告，不写飞书或正式 HTML。

执行顺序：

1. 固定 GitHub `main` 的一个提交，读取同版本地块页面、证照核验结果和成交公告来源。仅接受 48 小时内的成功实时采集结果；过期、缺失、结构异常或地块数量回退时停止。
2. 按完整成交公告编号更新同 Base 的地块目录，仅新增缺失记录、更新发生变化的采集字段，不删除地块或改反向关联。
3. 从项目主表读取名称、开发企业、预售证和现有关系，以规则匹配。金额、成交日期、项目名称、品牌等原业务字段不会被此程序回写。
4. 无冲突的“预售证完整编号 + 开发企业法人名称”均与已归属到该地块的有效住宅官方证照一致时，可自动确认。证照自身须有效、在成交之后且来自住建委或规自委来源。
5. 备案名包含完整规划宗地编号、该编号同时出现在本地块及官方规划证照、且开发企业一致时，可自动确认。不会通过相似名称、简称、品牌名或列表序号确认。
6. 同名或名称包含仅产生候选；多个项目使用同一命中证号、开发主体冲突等转“需人工确认”。分期后缀不删除；一个地块下的多个项目不合并。
7. 已确认关系保留，人工更改或撤销的结果不被程序自动恢复。输入指纹及上次写入值保存在本地状态文件；相同输入不重复写入。新增地块会触发重新比较，实际只写变化的关系。
8. 写前复读，写后核验，最终只有“已确认”关系导入本地网页。无 `projectCode` 时只展示项目名称，不拿官方 projectID 或飞书记录 ID 代替。

每次运行保存写前快照、写入计划、网页预览及结果摘要到 `reports/land-project-sync/<运行时间>/`。首次申请写入若响应不确定，不自动重放创建请求；下次先读目录。CLI 不提供事务性条件更新，写前复读只能缩小人工同时编辑的竞争窗口，建议在运行期间避免编辑关联字段。

## 6404 项目编码补齐

`scripts/sync_land_tracker_project_codes.py` 为已经确认地块关系的项目补齐真实外部数据编码，不负责确认地块关系。编码来源为 Dataset `6404`（项目按月维度的销售信息），数据源 `sr_ads_tdda`；同一项目会重复出现在不同月份，不能将月份记录当作不同项目。

调度先用已授权 Dataset 连接器读取定义再查询，当前参数为 `{}`。仅保留 `projectName`、`projectCode` 并按二元组去重，不保存金额、套数等无关字段。完整成功查询后生成本地 `reports/land-project-codes/source-6404.json`：

```json
{
  "datasetCode": "6404",
  "datasourceCode": "sr_ads_tdda",
  "retrievedAt": "实际查询完成的带时区时间",
  "complete": true,
  "records": [{"projectName": "来源项目名", "projectCode": "来源真实编码"}]
}
```

```sh
.venv/bin/python scripts/sync_land_tracker_project_codes.py --source reports/land-project-codes/source-6404.json --apply --lark-cli '<已授权CLI路径>'
```

- 默认不带 `--apply` 只试算。首次授权初始化才使用 `--init-state`；以后缺少状态须恢复备份，不能自动重建。
- 只处理有“已确认”地块关系且编码为空的记录。读取三个现有名称字段，只规范全半角、空白和间隔点，不删除品牌、分期，不做模糊匹配或拆分名称。
- 三个名称命中的编码并集必须恰好一个，而且没有被另一条项目记录使用。多编码、无匹配、未确认或共享编码均不写入，不按大小写、月份或列表顺序猜测。
- 仅写 `projectCode`，保留已填编码和人工清空历史，不改任何原业务字段或关系。写前复读，写后全字段比较，只允许计划中的编码变化；失败即停止后续写入。
- API 响应不确定时保留 `pending`，下次先读回，验证确已全部写入后才继续；部分写入或读回不一致需人工处理，不重复发起。
- 快照仅允许 48 小时内完整成功结果。日志、写前/读回快照、写入计划、预览与状态仅保存在本地 `reports/land-project-codes/`，不提交公共仓库。
- 读回核验后更新本地网页的 `linkedProjects`。一个地块下多个项目分别保留；无编码继续显示名称。真实编码可以是 UUID，不要求以 `P` 开头。

这套名称对照仅用于补齐已确认关系的编码，不替代官方证号与开发企业核验规则。母工程仍需按下文接收 `postMessage` 并打开真实项目详情；编码写入成功不等于母工程联调通过。

## 页面跳转约定

项目名保持蓝色下划线外观，但使用 `type="button"` 的按钮，不再生成带 `href`、`target` 的项目链接。所有项目点击只请求母工程处理，不直接跳转、不打开新标签页、不做延时跳转兜底。证照来源链接和地块地图按钮不受影响。

在已识别的 `https://om.gtcloud.cn` 母工程 iframe 内，鼠标主键点击（含 Ctrl/Command/Shift/Alt 修饰的 click 事件）以及 Enter/空格激活发送以下消息；中键、右键和 macOS 的 Control+点击上下文菜单不激活。独立打开网页、未能识别母工程或母工程来源不匹配时不发送、不跳转。没有真实编码的项目仍只显示普通文字。

```json
{
  "type": "chatbi2:open-project-detail",
  "requestId": "每次点击生成的请求标识",
  "projectCode": "所点击项目的真实编码",
  "projectName": "所点击项目名称",
  "landCode": "地块编号",
  "landName": "地块名称",
  "url": "该项目的外部数据URL",
  "source": "land_tracker_dashboard_20260614"
}
```

`postMessage` 的 `targetOrigin` 使用 `"*"`，不在子页面指定母工程地址。消息内的 `url` 仅为兼容已有协议保留的路由元数据，子页面不执行该 URL。母工程应核验发送方 origin、iframe window、消息类型及编码，然后跳转路由并将编码传给外部数据 iframe。修改或联调真实母工程、外部项目详情接收端不在本次改动内。
