## 数据链路

GitHub 每日官方采集和交叉核验全部成功、页面测试通过后，运行
`python scripts/land_tracker_feishu.py`，与网页一起提交并发布
`land_tracker_dashboard_20260614/feishu-feed.json`。
飞书原生工作流每天北京时间 15:00 GET 该公开数据文件并写入地块跟踪明细。
不依赖本机开机，不向 GitHub 配置飞书个人登录令牌。

## 写入规则

- 全量扫描最新成功快照，不按成交日期筛选增量；旧地块新证照同样更新。
- 以交易公告地块编号查找：无记录则新增，一条则更新，多条则跳过并通知创建者。
- 源端按标准化编号检查唯一性；展示编号保留原字符格式，以匹配首次导入数据。
  飞书内不要手工改地块编号，否则会被视为另一条记录。
- 基础字段更新后，仅逐项写入非空项目名称、板块、品牌、证照和来源。
  空白不会清空旧内容。人工备注从不读取、公开或覆盖。
- 五类证照日期直接继承上游官方匹配结果，不在工作流内推测或二次取最小值。
- 数据文件保留北京时间对应的毫秒时间戳，工作流通过 `TODATE` 将同一日期的
  `YYYY/MM/DD HH:mm:ss` 文本转换为原生日期写入；金额和楼面价使用 JSON 数字。
- 证照核验时间来自官方采集快照；同步时间为飞书实际写入时间，两者不可混用。
- 仅发布最近 48 小时成功的 live 快照，拒绝离线重放、未来时间、重复编号和空集。
  工作流再次检查状态、版本、数量和有效期，失败分支通知创建者。

## 故障与恢复

源采集失败不会发布新快照。旧快照 48 小时后失效，飞书停止更新并提醒。
GitHub 定时任务可能排队；15:00 同步不保证上游当日已完成，以核验时间为准。
循环使用失败即停止：飞书不提供跨 75 行的事务回滚，故中断前部分行可能已更新。
修复后重跑，按编号收敛，不重复插入已经成功新增的行。源文件只生成白名单字段。
网络连接失败或飞书写入异常可能在条件判断之前终止，请检查飞书工作流运行日志；
业务异常通知分支不等于对平台所有运行异常的捕获。

## 维护

工作流草稿由 `build_workflow` 生成，包含定时触发、HTTP、有效性检查、两个顺序循环、
唯一匹配检查、新增/更新分支、非空字段路由与异常提醒。
需要调整字段时，同步修改脚本中的 CORE/OPTIONAL、测试以及飞书完整工作流定义。
工作流定义含个人通知接收者，保存在本地交付目录，不提交到公开仓库。

CLI 1.0.86 不能保留原生工作流公式：get 返回的公式值是空数组。
因此先用 CLI 导入停用草稿，再在飞书页面绑定三个日期转换公式及有效期公式，
最后把版本门禁从 -1 改为 1。之后不能用 CLI 读回再全量覆盖，否则会丢失公式。
两个 Loop 的数据源分别是公开接口的 rows 和 updates，避免嵌套循环的类型推断限制。
飞书单循环最多 1000 项；任一快照的非空可选字段更新超过 1000 项时，
导出脚本会失败并要求分批，绝不静默截断。流程中的日期转换辅助字段不属于业务数据。
多条件分支使用排他模式，避免当前服务端单分支并行模式的编译错误。

验证：`python -m unittest discover -s scripts/tests -p 'test_land_tracker*.py' -v`。
