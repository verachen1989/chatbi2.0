# 地块跟踪：项目名称、品牌与证照补充采集

## 范围与原则

成交主表以交易文件编号为主键，一笔包含多个子地块的交易仍为一行。项目与证照采集在成交阶段之后执行，读取同一份待更新数据。自动补充空值；旧值与新证据冲突时不覆盖，而是保留候选、来源和待核原因。

**自动采集不等于每个字段都能自动确认。** 没有查询结果、来源无法访问、记录不能唯一关联地块，是三种不同状态；都不能写成“尚未取证”。已有值也不因这次没查到而清空。

## 公开采集路径

| 字段 | 入口与查询方式 | 取值口径 |
| --- | --- | --- |
| 建设工程规划许可证 | [规自委规划许可公示](https://yewu.ghzrzyw.beijing.gov.cn/gwxxfb/cxghjsgcgh/jsgcgh.html)，按规划地块编号检索，逐页读取列表及详情 | `faWenRiQi` 发文日期；不是首次公示日期 `scgsrq`。只接受已发正本且未注销的住宅工程记录 |
| 建设方案 | [住建委项目建设方案](http://bjjs.zjw.beijing.gov.cn/eportal/ui?pageId=53618389)，用地块编号检索标题并读取正文 | 首次有效住宅方案的可见“发布时间”；不是正文中的计划开工日，也不是网页模板的历史 `PubDate` |
| 施工证时间 | [施工许可查询](http://bjjs.zjw.beijing.gov.cn/eportal/ui?pageId=53618592)，按建设单位查询全部分页并读取详情 | 有效住宅主体工程施工许可证的“发证日期”；排除土方、桩基、基坑、临时及售楼处装修工程 |
| 首个预售证 | [预售许可查询](http://bjjs.zjw.beijing.gov.cn/eportal/ui?pageId=307670&isTrue=0)，按开发企业查询全部分页并读取项目详情 | 与本宗地关联且含可售住宅楼栋、住宅套数大于零的最早发证日；排除仅车库、库房等供应 |
| 首个竣工备案（原列名“首个竣工证”） | [竣工验收备案查询](http://bjjs.zjw.beijing.gov.cn/eportal/ui?pageId=53618638)，按建设单位查询 | 目前取得的是住宅工程最早“竣工备案日期”，**不是另行核验的竣工证发证日**。页面按实际口径改列名，底层仍用 `firstCompletion` 保持兼容 |
| 项目名称 | 已关联的官方预售详情；有明确证据时另存企业官网公布的推广案名 | 备案名与推广名分开存储。空值可补官方备案名；不拿备案名覆盖现有推广名 |
| 所属地产品牌 | 企业官网的具体项目公告，需同时证明品牌、项目与精确地块 | 当前使用人工核准的官方来源清单，程序自动重验原文并回填。**尚未实现互联网全量品牌公告自动发现**；不能从项目公司简称直接猜母品牌 |

这些入口为公开查询，不需要登录公共资源综合交易系统。部分住建委公开页面仅能以 HTTP 正常访问，按官网实际公开入口读取，不提交账户密码，也不关闭 HTTPS 证书验证。

## 地块关联规则

1. 交易文件编号用于主表去重；工程里的规划地块编号用于跨系统关联，两者不能混用。
2. 对全半角、空白、连接符归一化。对 `HD00-1408-0034、0049、0040` 等同前缀编号展开，按完整编号比较，不能用模糊子串命中。
3. 规划许可、建设方案、施工许可和竣工备案，要求工程标题中的精确地块编号与行政区/建设位置共同一致，而且只能落到一笔交易。
4. 建设方案中的四至可能提到相邻地块，因此只用标题确定地块身份，不能把正文任意编号都当成归属。
5. 预售详情通常没有地块编号，优先用“规划许可证号完全一致 + 开发企业与该许可建设单位一致”桥接。详情引用的全部规划许可证都必须完成关联，且唯一指向同一宗地。跨宗地或仅同名、同公司均不自动确认。
6. 建设单位先从已匹配的住宅规划/方案等证据发现，再以其全称查询后续证照。不从纯电力等配套工程提取供电单位当作项目开发企业。竞得人的单一公司全称可用于发现候选，但公司名相同本身不是回填依据。
7. 每个节点在已核实、有效、住宅用途且不早于成交日、不晚于运行日的记录中取最早日期。正文只含 R2 土地用途，不代表本次工程必然是住宅楼。
8. 先规划、后预售的证号桥接是匹配依据，不强制五类日期机械递增。建设方案发布时间可能晚于其他节点，异常需看原文，不人为调整日期。

## 保留证据与人工复核

- `confirmed`：本轮证据与展示值一致，日期/品牌可点击查看来源。规划许可的官方接口只返回 JSON，其蓝色日期先打开表内的可读采集记录，展示证号、批准日期、工程、建设单位和位置；底部另附官网查询入口及明确标注的原始数据入口，不将采集记录冒充电子证照。
- `alias_confirmed`：找到与本宗地关联的备案名或另一个有证据的案名，保留现有名称，别名进入证据文件。此状态不证明旧推广名本身正确，旧名称与官方名称的关系仍可人工复核。
- `conflict`：旧值与候选不一致，或存量日期早于成交。旧值保留，页面标“待核”。
- `legacy_unverified`：原有字段本轮没有找到可确认的证据，不能当成已重新核实。
- `not_reconfirmed`：以前有证据，本轮未重新确认，保留历史证据但撤下已确认状态。

`data/land_tracker_enrichment.json` 保存逐地块、逐字段的状态、显示值、候选值、官方记录、证号、链接及匹配依据。`LAND_ROWS.fieldEvidence` 仅保存页面展示所需的简化信息。完整未匹配候选也写入报告，便于人工查错，不静默丢弃。

项目与品牌的官方证据配置在 `data/land_tracker_identity_sources.json`。新增配置必须提供交易编号、精确地块编号、公告日期、企业官网 URL、必需原文片段，以及名称/品牌中的至少一项，并先人工确认它们在正文中的关联关系。两项可以分别核验，例如品牌明确但案名未公布时只补品牌；没有营销案名证据时仍可通过预售资料补备案名。允许访问的企业域名需显式登记，不能任意抓取外部链接。

## 更新安全与审计

- 列表和详情交叉校验证号、日期、主体；核对分页总数、当前页和重复项。真实零结果须有正常分页结构，登录页/错误页不算零结果。
- 每次请求间隔至少 0.5 秒，有限超时重试；不绕过验证码、登录或权限控制。响应跳转到其他入口时停止该次查询。
- 一个查询中途失败时撤回它产生的部分证据；本轮任一来源查询失败则整个补充阶段失败，不更新正式页面、不提交发布。
- 原始响应按请求 URL 和参数的摘要保存，附原始请求参数。可离线重放同一轮证据，不依赖网站后来是否改变。
- `collectionMode` 区分联网、续跑与快照重放；`checkedAt` 是本次处理时间，不将快照重放表述为当日重新联网核验。
- 页面仍是静态 HTML。爬取发生在 Python/GitHub Actions 中，不让浏览器用户承担抓取，也不在前端存放采集登录凭据。
- 品牌来源缺失、地块多义、施工主体与拿地主体不同、联合开发、日期冲突及首次记录缺失，都可能需要人工复核。

## 本地运行与验收

在仓库根目录使用 Python 3.12 和系统 curl：

```bash
# 单元测试，包含官网原文样本、匹配、排除、冲突与失败回滚
python -m unittest discover -s scripts/tests -p 'test_land_tracker*.py' -v
node scripts/tests/test_land_tracker_ui.cjs

# 先获取成交候选，再补充项目与证照；不改正式页
python scripts/update_land_tracker.py --dry-run
python scripts/update_land_tracker_enrichment.py \
  --page reports/land-tracker/proposed.html --dry-run

# 只回查当前页面中的地块
python scripts/update_land_tracker_enrichment.py --dry-run

# 使用同一次的全部原文重放；缺快照会失败，不偷偷联网补数据
python scripts/update_land_tracker_enrichment.py --dry-run \
  --snapshot-dir reports/land-tracker/enrichment/raw \
  --report-dir reports/land-replay

# 已核验后写入本地，命令本身不会推送 Git
python scripts/update_land_tracker_enrichment.py --apply \
  --snapshot-dir reports/land-tracker/enrichment/raw

# 页面回归
python scripts/test_land_tracker_browser.py
```

中断后允许用 `--resume-dir <同一轮 enrichment/raw>` 复用已抓到的响应并继续抓缺失请求。该参数用于人工恢复，定时任务默认不用旧缓存，避免把昨日快照当成今日重新核验。

报告位置：`reports/land-tracker/enrichment/report.md`、`report.json`、`candidates.json`、`raw/`。验收应抽查新增名称/日期的官网原文、每个冲突的前后值、非住宅排除和跨宗地未匹配记录；同一快照重复应用不应新增数据或改变已有值。

工作流在成交采集之后运行本模块，只有两阶段采集、校验与页面回归全部通过才提交发布。已有的北京时间 08:30 调度保留，不另建一套定时器。
